    How it works

    Agentic Brain: one encrypted memory for Claude Code, Claude Desktop, Cursor, Codex and Antigravity, synced through your own GitHub, that learns from your work.

    View repo
    The 10-second version

    Every session, your AI tools figure things out, then forget them. This turns that work into reusable memory.

    So you (and the AI) never start from zero on a codebase you've already worked in, and you stop paying tokens to re-learn what you already figured out. One brain serves every AI tool you use, every project, every Mac, stored in your GitHub, encrypted with your key. The five words on the right are the whole system; Using it every day shows what you'll actually see.

    Your key: the one thing to back up

    Your cloud backup is locked with a key that lives only in this Mac's Keychain. Moving to a new Mac does not bring it along, so save it in your password manager. Never paste it into a chat.

    brain key import: on a new Mac; asks for the key and hides it as you paste.
    brain key rotate: if the key was exposed, re-encrypts the backup with a new key (never printed; it offers a passphrase backup); the old one stops working.
    brain key show: prints the public half (safe to share).
    brain sync: runs daily at 09:30; merges other Macs, then uploads.

    1 · What's an "observation"?

    The atom of the whole system. 10,283 of them are your memory.

    Think of an observation as a note-card your AI writes to itself after each step: like a commit message, but for what it learned, not what it changed. As you work, the brain keeps only the durable takeaway (not the whole chat) in a fixed shape:

    • type: what kind of moment it was: bugfix, feature, decision, discovery… (so you can later ask "show me every bugfix in this file")
    • title + subtitle: the one-line what-happened
    • facts: the specific, reusable details, in plain sentences
    • files · concepts · project · timestamp: the tags that make it findable

    Two properties do all the work: it's typed (filterable, not a wall of text) and compressed (a whole investigation shrinks to a few sentences). That's why looking something up later costs almost nothing. Here's a real one from this repo.

    bugfixmy-app · obs #10377
    Database snapshot before packing to preserve WAL entries

    Memory packing now uses VACUUM INTO to capture uncommitted WAL rows before encryption.

    Facts
    • claude-mem runs SQLite in WAL mode; newest rows live in a separate -wal file
    • Raw DB copy omitted them, silently losing the newest observations on sync
    • snapshotDb() folds WAL into a consistent snapshot without mutating the live DB
    bin/lib/bundle.mjs problem-solution · gotcha
    Cost 3,334 tokens to figure out once · ~300 tokens to recall forever.

    How to read it: the SQLite specifics don't need to be yours. Notice the shape every observation shares: a problem, its cause, the fix, and where it lives. That shape is what makes it reusable. And the token line is the whole system in miniature: solving that bug the first time was expensive (3,334 tokens of reading, reasoning, testing), but the lesson is tiny (~300 tokens). Pay to learn once; recall for a tenth of the cost, forever, and never rediscover the same bug.

    2 · What's "dream"?

    The consolidation pass: it turns a pile of observations into knowledge you can read.

    Ten thousand raw observations is a haystack. Dream is the pass that consolidates them, like what a brain does in sleep. It reads the pile and writes it up into a compounding wiki/:

    • Cross-referenced pages per project & topic, updated in place, so knowledge builds up instead of being regenerated from scratch
    • A daily briefing of where your attention went
    • A lint pass that flags contradictions, stale claims, and orphans to reconcile
    • Your hand-written ## Notes are never overwritten

    dream is a faithful implementation of Karpathy's "LLM Wiki" pattern: his three layers (raw sources, wiki, a SCHEMA.md) and three operations (ingest · query · lint), where the LLM does the grunt work of summarizing and cross-referencing. The twist here: the "raw sources" aren't documents you feed it, they're your work, captured automatically. Run it nightly or hit Dream now on the Dream tab.

    3 · The architecture

    Five layers on one database. Each is small, deterministic, and verifiable.

    01 CAPTURE
    Claude Code · Codex · Cursor · Antigravity CLI (automatic) + Claude Desktop (via brain_remember)
    Each tool's sessions are read from disk after the fact, so a capture problem can never break a live session, and deduped on a session id, so nothing double-counts. Chat apps have no readable transcript, so their AI saves what matters with the brain_remember tool. If you already use claude-mem, its memory imports in.
    02 STORE
    One SQLite DB, ~/.claude-brain/brain.db, the single source of truth
    Every tool, every project pours into the same database. 10,283 observations across 18 projects, in one place, with secrets scrubbed before they are stored.
    03 DISTILL
    dream to wiki · distill to learnings · mine to workflows
    Raw memory is compiled into higher-order knowledge: wiki pages, reusable fixes ("learnings"), and recurring rituals.
    04 RANK + INJECT
    BM25 + outcome scores pick the relevant few, into a ~2k-token digest
    Three ways in: the digest is written into each tool's context file (CLAUDE.md / AGENTS.md / GEMINI.md); Claude Code gets this folder's timeline at startup; and every tool can ask on demand through the MCP tools brain_context · brain_recall · brain_remember. Budgeted and deduped.
    05 MEASURE
    brain eval scores recall on your own history, then loops back to 01
    ~20 questions with verifiable answers. Gates every change to distill/inject/search so quality can't silently regress. Now at 65% (from a 15% baseline).
    Portability arm. The DB + wiki + learnings are age-encrypted into one brain.age file, stored as a Release asset in your own private GitHub repo; GitHub only ever holds ciphertext. A daily sync (09:30) merges what other Macs pushed before uploading, so two machines never overwrite each other, and it refuses to replace a backup it can't read. A new Mac runs the installer, imports the key, and restores the whole brain. Skills & agents travel as plaintext; your key never leaves your Keychain.

    4 · How this saves tokens

    Context isn't free. You pay to learn a thing once, not every session.

    The problem it removes

    To make an AI useful on your codebase, normally you either:

    re-read files & past transcripts every session: thousands of tokens burned re-establishing what you already knew, or

    start cold and re-derive it, repeating the same investigation, and the same bug.

    With the brain, observations are pre-compressed and only the relevant few are surfaced (ranked, then budgeted to ~2k tokens). You pay the learning tax once; recall is cheap forever.

    Measured on this very session

    Loading this conversation's context surfaced 48 observations standing in for 170,022 tokens of past work, for a fraction of the cost:

    fewer tokens to walk in already knowing 170k tokens' worth of history. The WAL bug above is the pattern in miniature: 3,334t to discover, ~300t to recall.
