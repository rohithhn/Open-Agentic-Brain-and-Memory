# Code of Conduct

## Our standard

This is a small, private beta — right now, a handful of individually invited testers and one
maintainer. The standard is simple: be respectful, be constructive, and don't make this space
unpleasant for anyone else in it.

In practice:

- Give feedback on the tool and the problems you hit, not on people.
- Assume good faith — this is early, undertested software from one person; bug reports and
  blunt criticism of the *software* are exactly what a beta is for.
- No harassment, insults, discriminatory language, or personal attacks, in issues, pull
  requests, or any other communication related to this project.
- Respect that other testers' data — their private repo, their `age` key, their captured
  memory — is theirs. Don't probe, access, or discuss another tester's data without their
  explicit permission.

## Scope

This applies to any space connected to this project: GitHub issues and pull requests, direct
communication with the maintainer about the beta, and anywhere else this project is discussed
in a context tied back to it.

## Enforcement

Because this is presently an individually-invited private beta, enforcement is direct: the
maintainer may remove content, decline further interaction, or revoke a tester's access to the
beta for behavior that violates this standard. There is no formal committee or appeals process
at this scale — if you believe an enforcement decision was made in error, say so directly to
the maintainer.

## Reporting

If something happens that concerns you — from another tester or otherwise — contact the
maintainer directly (the same contact used for security reports works for this too; see
`SECURITY.md`). Reports are handled as discreetly as the situation allows given the small size
of the group.
